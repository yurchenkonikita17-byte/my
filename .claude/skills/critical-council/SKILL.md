# Critical council

Цель — не дать ответу подстроиться под пользователя. Схема взята из
[karpathy/llm-council](https://github.com/karpathy/llm-council) (`backend/council.py`):

1. **Stage 1** — несколько участников отвечают независимо, не видя друг друга.
2. **Stage 2** — каждый оценивает анонимизированные ответы (Response A, B, C…) и ранжирует их.
3. **Stage 3** — председатель сводит всё в один ответ.

Отличие от оригинала: участники — субагенты с разными критическими ролями, а не только
разные модели, и в stage 2 отдельно ищется поддакивание.

## Режимы

- **full** (по умолчанию для важных решений: деньги, карьера, здоровье, архитектура,
  необратимые шаги) — 4 участника, 4 рецензента.
- **lite** (короткие вопросы «что лучше A или B») — 3 участника, 1 рецензент.
- **multi-model** — если задан `OPENROUTER_API_KEY`, stage 1–2 можно прогнать на моделях
  разных вендоров через `scripts/council.py` (см. ниже). Это сильнее, чем субагенты одной
  модели: у них общие слепые пятна.

Если пользователь сам сказал «быстро» или «без консилиума» — не запускай его.

## Stage 0 — нейтрализация вопроса (делаешь сам)

Запиши два текста:

- **NEUTRAL_QUESTION** — суть вопроса и факты, без позиции пользователя, без оценочных слов
  («я уверен», «это же отличная идея», «все говорят»), без намёка на желаемый ответ.
- **USER_POSITION** — что пользователь, судя по формулировке, хочет услышать. Если позиции
  нет — «не выражена».

Если в вопросе есть ссылки, файлы или код — собери нужный контекст сам и вложи его в оба
текста, чтобы участники не тратили время на поиск.

## Stage 1 — независимые мнения

Запусти участников **параллельно, одним сообщением** через Agent tool
(`subagent_type: general-purpose`, `run_in_background: false`). Для разнообразия задай
разным участникам разные `model` (например `opus`, `sonnet`, `haiku`).

| Роль | Что получает | Задача |
|---|---|---|
| Независимый | только NEUTRAL_QUESTION | ответить по существу, не зная, чего хочет пользователь |
| Адвокат дьявола | NEUTRAL_QUESTION + USER_POSITION | построить самый сильный аргумент **против** позиции пользователя |
| Эмпирик | NEUTRAL_QUESTION | базовые ставки, данные, исследования; что известно, а что домыслы |
| Практик (только full) | NEUTRAL_QUESTION | риски, стоимость, сценарии провала, последствия второго порядка |

В lite-режиме оставь Независимого, Адвоката дьявола и Эмпирика.

Промпт каждому участнику:

```
Ты участник критического консилиума. Твоя роль: <РОЛЬ> — <задача из таблицы>.
Ты не обязан никому понравиться. Согласие без доказательств — ошибка.

Вопрос:
<NEUTRAL_QUESTION>
[Только для адвоката дьявола: Позиция пользователя: <USER_POSITION>]

Ответь строго в формате:
ВЕРДИКТ: <одна-две фразы>
УВЕРЕННОСТЬ: <0–100%>
ДОВОДЫ: <3–6 пунктов, каждый с обоснованием>
СИЛЬНЕЙШЕЕ ВОЗРАЖЕНИЕ МОЕМУ ВЕРДИКТУ: <честно>
ЧТО ИЗМЕНИЛО БЫ МОЁ МНЕНИЕ: <конкретные факты или условия>
Не более 350 слов. Ничего не выполняй и не меняй в файлах — только рассуждай.
```

## Stage 2 — анонимная перекрёстная рецензия

1. Перемешай ответы stage 1 и подпиши их `Response A`, `Response B`, … Запомни соответствие
   метка → роль, но рецензентам его не показывай (как `label_to_model` у Карпатого).
2. **full**: снова запусти участников параллельно, каждому — все ответы. **lite**: один
   рецензент (`model: opus`).

Промпт рецензенту:

```
Ты оцениваешь анонимные ответы на вопрос:
<NEUTRAL_QUESTION>
Позиция, которую занимает пользователь: <USER_POSITION>

<Response A: …>
<Response B: …>
…

Для каждого ответа:
- что верно и что ошибочно или не доказано;
- ПОДДАКИВАНИЕ: соглашается ли он с позицией пользователя без самостоятельных доводов (да/нет, почему);
- какие важные соображения упущены.

Затем перечисли ошибки, которые повторяются в нескольких ответах (общая слепая зона).

В конце строго в таком виде:
FINAL RANKING:
1. Response X
2. Response Y
…
Не более 400 слов.
```

3. Посчитай средний ранг каждой метки (как `calculate_aggregate_rankings`): чем меньше,
   тем лучше. Ответы, которые рецензенты пометили как поддакивающие, при синтезе весят меньше.

## Stage 3 — председатель (ты)

Правила синтеза:

- Начинай с вердикта. Без похвалы вопросу и без «отличная идея», «вы абсолютно правы».
- Если консилиум не согласен с пользователем — скажи это прямо в первой фразе и объясни почему.
- Соглашайся с пользователем только если к этому пришёл участник, **не знавший** его позиции
  (Независимый или Эмпирик), и только с его доводами.
- Не усредняй мнения ради компромисса: если сильные доводы на одной стороне — займи её.
- Явно назови разногласия, которые консилиум не разрешил, и общую слепую зону из stage 2.
- Дай итоговую уверенность и что изменило бы вывод.
- Не выдумывай данные, которых не было в ответах участников или в контексте.

Формат ответа пользователю:

```
**Вердикт:** …
**Уверенность:** N%

**Почему:** 3–5 пунктов.
**Где вы, возможно, неправы:** … (или «консилиум согласен, потому что …»)
**Разногласия в консилиуме:** …
**Что изменило бы вывод:** …

<details><summary>Консилиум</summary>
Рейтинг: Response B (роль, ср. ранг 1.3), …; по одной строке на каждого участника.
</details>
```

Если пользователь вернётся с возражением, не сдавайся просто из-за нажима: меняй вывод
только при новом факте или доводе и скажи, какой именно довод тебя переубедил.

## Multi-model режим (опционально)

`scripts/council.py` — порт stage 1–2 из llm-council на стандартной библиотеке Python.
Нужен `OPENROUTER_API_KEY` и доступ к `openrouter.ai` в сетевой политике окружения.

```bash
python3 .claude/skills/critical-council/scripts/council.py \
  --question "<NEUTRAL_QUESTION>" --position "<USER_POSITION>" > /tmp/council.json
```

Модели задаются через `COUNCIL_MODELS` (через запятую). Скрипт возвращает JSON с ответами,
рецензиями, `label_to_model` и `aggregate_rankings`; stage 3 делаешь сам по правилам выше.
Если ключа нет или запрос не прошёл — используй субагентов.
